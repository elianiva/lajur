# Using Vite+, the Unified Toolchain for the Web

This project is using Vite+, a unified toolchain built on top of Vite, Rolldown, Vitest, tsdown, Oxlint, Oxfmt, and Vite Task. Vite+ wraps runtime management, package management, and frontend tooling in a single global CLI called `vp`. Vite+ is distinct from Vite, and it invokes Vite through `vp dev` and `vp build`. Run `vp help` to print a list of commands and `vp <command> --help` for information about a specific command.

Docs are local at `node_modules/vite-plus/docs` or online at https://viteplus.dev/guide/.

## Built-in Commands vs Scripts

`vp <name>` runs a built-in command. `vp run <name>` runs a `package.json` script or a `vite.config.ts` task. Scripts cannot overwrite built-ins, so `vp dev` and `vp run dev` may do different things. Check `package.json` and `vite.config.ts` first, and run `vp run <name>` when the project defines a script or task with that name.

## Running Scripts

Run TypeScript and JavaScript files with `vpx <file>`, for example `vpx ./scripts/seed.ts --dry-run`. It handles enums, decorators, JSX, and tsconfig `paths`, so do not add `tsx` or `ts-node` to run scripts. `vpx --watch <file>` reruns the file when a file it uses changes, in place of `tsx watch`. `vp node <file>` runs plain Node.js.

## Tool Versions

Run `vp toolchain` to show versions and relationships in the active Vite+
release. Add a tool name to select part of the graph. For example, run
`vp toolchain vite`. Use `--global` to ignore the local `vite-plus` package. Use
`vp why <package>` to show the package-manager dependency graph.

## Review Checklist

- [ ] Run `vp install` after pulling remote changes and before getting started.
- [ ] Run `vp check` and `vp test` to format, lint, type check and test changes.
- [ ] Check if there are `vite.config.ts` tasks or `package.json` scripts necessary for validation, run via `vp run <script>`.
- [ ] If setup, runtime, or package-manager behavior looks wrong, run `vp env doctor` and include its output when asking for help.

## The game

- `logic/game.bend` is the model: the route through the world, the car, traffic, the
  speed ceiling and the verdict. `logic/lokal.bend` turns a tree block's
  streets into the ways the car drives. `logic/PROOF.bend` proves the claims.
- `src/game.mjs` is generated by the Vite plugin (`vp dev`, `vp build`) and by
  `vp run proof`'s sibling `vp run logic`. Never edit it, and never reimplement
  a rule in TypeScript to work around it.
- TypeScript reads the model and draws it: three.js meshes, camera follow, HUD
  formatting, keyboard mapping. If a change would put a decision in `src/`, it
  belongs in `logic/game.bend` with a law next to it.
- `vp check` must pass before a change counts; so must `vp run proof`.

## The lab

- `/lab.html` opens on the city (`Town`); `#shelf` shows every asset row.
- `#world` is the generated world, made cell by cell, each cell a function of
  (seed, i, j), so cells tile in any order. `logic/world.bend` is the lattice,
  the roads, each cell's frame, its collectors, the entrance slots, what each
  block becomes and the streets inside it; its laws are in
  `logic/PROOF_WORLD.bend`. `logic/parcels.bend` places the lots, courts and
  trees on each cell. `src/world/cells.ts` and `parcels.ts` read them, and
  `plan.ts` draws it as a flat SVG for a minimap or
  preview. The game drives through it, drawn by `src/render/town.ts`, the
  same renderer as `#world`. `vp run plan` checks it.
- The city is drawn by the NPR studio: the look the game drives, plus five
  more in `src/lab/npr.ts`, sliders for their bands, shadow stain, rim,
  outline and grade, and the panel that binds them in `src/lab/studio.ts`.
- The shading itself is `src/render/look.ts` and is shared with the game. A new
  knob belongs there so every look can use it; a preset belongs in `npr.ts`,
  unless the game drives with it, and then it is the first entry of `looks`.
